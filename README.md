# «Путь» — фронтенд для VK Mini App

Обычный HTML/CSS/JS **без сборки** — специально, чтобы можно было выложить на
GitHub Pages точно так же, как вы уже делали с прошлой HTML-игрой: просто
загрузить файлы в репозиторий, ничего собирать/компилировать не нужно.

## Что уже готово

Полный цикл регистрации и школьного экзамена: авторизация → вопрос за вопросом →
один из четырёх исходов (студент / выбор профессии / завод-или-криминал / ПДД).
Дальше по тому же принципу подключим профиль, магазин, работу, криминал,
государство, чаты — backend для всех них уже полностью готов, дело за экраном.

## Как протестировать прямо сейчас, без VK и без хостинга

**Шаг 1.** Запустите backend локально (см. README проекта `social-rpg-vk-api`):
```
pip install -r requirements.txt --break-system-packages
```
В `.env` этого проекта поставьте `DEV_MODE=true`, впишите `DATABASE_URL` от
своей базы (можно локальный Postgres, можно тот же, что у Telegram-бота).
```
uvicorn bot.main:app --reload
```

**Шаг 2.** Откройте `index.html` из этой папки в браузере (можно просто
двойным кликом, либо через `python3 -m http.server 5500` и открыть
`http://localhost:5500`).

**Шаг 3.** Увидите экран «Локальный тест» — впишите любой номер, нажмите
«Войти». Дальше пойдёт настоящий школьный экзамен, обращаясь к вашему
локальному backend.

**Важно:** `DEV_MODE=true` (и на backend, и в `js/config.js`) — только для
такого локального теста. Перед тем как дать ссылку кому-то ещё или подавать
на модерацию VK, обязательно верните `DEV_MODE=false` в обоих местах —
иначе любой человек сможет представиться любым игроком без проверки.

## Как выложить на GitHub Pages (как в прошлый раз)

1. Поправьте `js/config.js` — впишите настоящий адрес вашего backend (после
   того как задеплоите его на Railway или другой хостинг, как делали с ботом).
2. Поставьте `DEV_MODE = false` в `js/config.js`.
3. Загрузите содержимое этой папки в репозиторий на GitHub — так же, как
   загружали прошлую HTML-игру.
4. В настройках репозитория (Settings → Pages) включите публикацию из ветки
   `main`, корневая папка.
5. GitHub даст вам ссылку вида `https://ваш-логин.github.io/название-репозитория/`
   — вот её и нужно будет вписать в кабинет разработчика VK, в поля URL
   («Мобильное приложение» и «Десктопная версия сайта» на скриншотах, которые
   вы прислали).

## Как это тестировалось (честно, без розовых очков)

Реального браузера и npm в песочнице, где это писалось, не было — зато
неожиданно нашёлся Node.js, и с его помощью:
- Проверен синтаксис каждого файла (`node --check`)
- Реально импортированы все модули друг через друга — поймало бы любую
  опечатку в именах экспортов/импортов (аналог проверки сигнатур `db.*` в
  backend), 0 ошибок
- Прогнан весь путь `main()` с фейковым backend — и сценарий «нет VK, включён
  dev-режим», и сценарий «есть настоящие launch-параметры VK» — оба без
  исключений
- Пошагово пройден весь экзамен из двух вопросов с кликами по вариантам
  ответа — от первого вопроса до экрана результата, тоже без исключений

Того, что нельзя было проверить без настоящего браузера: как это выглядит
визуально, работает ли VK Bridge по-настоящему внутри VK, и реальные
CSS-стили. Это стоит проверить самим при первом локальном запуске (Шаг 2
выше) — если что-то будет выглядеть не так, пришлите скриншот, поправлю.
